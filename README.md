# Rewind ↶

**Track how the web changes, one screenshot at a time.**

웹사이트의 순간을 저장하고, 타임라인과 슬라이더로 변화를 비교하는 개인용 웹 타임머신입니다. 실제 Chromium으로 촬영하며 데이터는 내 컴퓨터에 보관합니다.

## 실행

Node.js **22.13 이상**이 필요합니다.

```bash
npm ci
npm run browser:install
npm start
```

브라우저에서 **http://127.0.0.1:3000** 에 접속합니다. Linux에서 브라우저 시스템 패키지 설치 시 관리자 권한을 요청할 수 있습니다. 필요한 패키지가 이미 설치되어 있다면 `npx playwright install chromium`으로 브라우저만 설치할 수 있습니다.

Ubuntu 24.04 x86_64에서 관리자 권한이 없다면 `npm run browser:libs:local`과 `npx playwright install chromium`을 실행하세요. 필요한 라이브러리를 시스템 대신 `data/browser-libs/` 안에 추출합니다. 이 대체 방법은 다른 Linux 배포판을 지원하지 않습니다.

1. **사이트 추가**에 공개 웹사이트 주소를 입력합니다.
2. 첫 촬영이 끝나면 사이트 카드를 열어 기록을 확인합니다.
3. **지금 촬영**으로 두 번째 기록을 남깁니다.
4. **전후 비교**에서 두 날짜를 선택하고 슬라이더를 움직입니다. 키보드 방향키도 지원합니다.

## 기능

- 실제 웹사이트 스크린샷: 가로 1440px, 상단 화면(1440 × 1000) 또는 전체 페이지 촬영, 라이트 모드, 한국어 로케일, 서울 시간대
- 사이트별 타임라인, 날짜별 기록 검색, 이전/다음 순간 이동
- 월별 기록 달력, 저장 사진·촬영 실패 표시, 날짜별 상세 이력과 사진 바로 열기
- 전후 비교 슬라이더, 나란히 보기, 좌우 교환, 전체 화면, PNG 다운로드
- 선택한 기록과 보기 방식을 복원하는 공유 링크
- 사이트별 분·시간 간격(1~43,200분 / 1~720시간) 또는 매일 지정 시각 자동 촬영, 다음 예정 안내
- 사이트 검색, 최근 기록순/추가순/이름순 정렬, 자동/수동/오류 필터
- 검색·필터·보기 방식 URL 복원, 기록을 보고 돌아오면 원래 목록 위치 유지
- 즐겨찾기 우선 정렬과 필터, 촬영 후에도 유지되는 사용자 지정 이름
- 카드/간결한 목록 보기, 현재 검색 결과에 있는 사이트를 한 번에 촬영
- 원본 이미지 확대·축소, 화면 맞춤, 마우스 드래그와 터치 스크롤로 이동
- 사이트 전체 또는 선택한 기록 1개 삭제, 삭제 전 대상 확인
- 여러 기록 선택·날짜 범위 선택·일괄 삭제, 페이지를 넘겨도 선택 유지
- 기록별 중요 표시·1,000자 메모, 중요 기록만 모아보기
- 변경 부분 강조 비교, 차이 기준 3단계, 변경 픽셀 비율과 비교 PNG 저장
- 사이트 보류·재개: 기존 기록과 자동 기록 설정을 유지하고 촬영에서 제외
- 비교할 왼쪽/오른쪽 기록을 타임라인에서 지정, 선택한 쪽의 원본 확대·PNG 저장
- 긴 타임라인은 12개씩 탐색하고 과거 기록 링크로 해당 묶음 바로 열기
- `/` 검색, `N` 추가, 방향키로 기록 이동, `C` 비교 전환, `?` 도움말
- 촬영 대기·진행·완료·실패 안내, 재시도, 서버 연결 끊김과 재연결 안내
- 삭제 대상 사이트와 기록 개수를 확인한 뒤 삭제
- 접근 거부 시 안내, 사이트 주소 변경 후 즉시 촬영, 직접 캡처한 화면 가져오기
- SQLite 메타데이터와 로컬 PNG 파일, 촬영 대기열과 실패 안내
- 반응형 한국어 UI, 키보드로 조작 가능한 비교 슬라이더

## 자동 기록과 저장

서버가 실행되는 동안 1분마다 일정을 확인하고 촬영할 차례가 된 사이트를 대기열에 추가합니다. 새 사이트의 첫 화면은 바로 촬영하고, 이후에는 사이트별로 선택한 일정을 사용합니다.

- **몇 분마다 / 몇 시간마다:** 마지막 촬영 시도부터 선택한 간격을 계산합니다. 1~43,200분 또는 1~720시간 사이의 정수를 지정하며 기존 설정은 같은 간격으로 유지합니다. 서버가 1분마다 확인하므로 실행 시각에는 최대 한 확인 주기와 앞선 촬영의 대기 시간이 더해질 수 있습니다.
- **매일 지정 시각:** 매일 `HH:MM`에 촬영합니다. 기준은 **한국 시간(Asia/Seoul)**이며 서버나 방문자의 기기 시간대가 달라도 같습니다. 선택한 시각 이후 이미 촬영을 시도했다면 그날 같은 일정으로 중복 시도하지 않습니다.

서버가 꺼진 동안에는 촬영하지 않습니다. 재실행하면 놓친 일정을 한 번만 촬영하고 다음 예정으로 이어갑니다. 실패도 시도한 일정으로 처리하여 무한 재시도하지 않습니다. 보류 상태에서는 두 일정 모두 실행하지 않습니다. 대기 중인 촬영이 있다면 차례대로 실행합니다.

새 사이트 등록 창에서 지정하거나 기존 사이트 화면의 **‘매 24시간’ / ‘매일 09:30’ 버튼** 또는 이름 옆 설정 버튼에서 수정합니다. 저장 전 다음 예정 시각을 미리 볼 수 있습니다. 일정만 바꾸어도 자동 기록을 켜거나 보류를 해제하지는 않습니다.

기본 저장 위치는 프로젝트 내 `data/`입니다.

```text
data/
  rewind.sqlite
  captures/<capture-id>.png
```

다른 위치에 보관하려면 `REWIND_DATA_DIR=/absolute/path npm start`를 사용합니다. 포트는 `PORT=3001 npm start`로 바꿀 수 있습니다. 백업은 앱을 종료한 후 `data/` 전체를 복사하세요. 런타임 데이터는 Git에서 제외됩니다.

외부 IP에서 접속하려면 `HOST=0.0.0.0 PORT=4317 npm start`로 실행한 뒤 `http://서버-IP:4317`에 접속합니다. 네트워크 방화벽이나 공유기가 있다면 해당 포트도 허용해야 합니다. 로그인 기능이 없으므로 접근 가능한 사람은 기록을 조회·촬영·삭제할 수 있습니다.

`.env.example`을 `.env.local`로 복사해 실행 설정을 저장할 수 있습니다. 셸에서 지정한 환경변수가 파일보다 우선합니다. `ALLOWED_IPS`에 쉼표로 구분한 IP 주소를 지정하면 해당 연결 IP만 화면·이미지·API에 접근할 수 있습니다. `X-Forwarded-For`와 `X-Real-IP`는 허용 판단에 사용하지 않습니다. NAT/VPN/프록시를 거치면 서버에서 보이는 연결 IP가 공인 IP와 다를 수 있습니다. 차단 로그는 `data/access-denied.log`에 저장되며, 동일 IP는 3초마다 한 번 기록하고 1MB를 넘으면 이전 파일 1개를 보관합니다.

이름과 즐겨찾기 설정은 SQLite에 저장되어 다른 기기에서도 유지됩니다. 보기 방식과 정렬 설정은 현재 브라우저에 저장됩니다. 새 버전을 실행하면 기존 데이터베이스에 설정 필드가 자동 추가되며 기록은 보존됩니다.

**사이트 관리 → 기록 보류**는 자동 촬영뿐 아니라 수동·일괄·로컬 관리 촬영에서도 사이트를 제외합니다. 저장된 기록 열람·비교·다운로드는 계속 가능하며, **기록 재개** 시 기존 자동/수동 설정을 유지합니다. **수동 기록**은 직접 촬영이 가능한 모드이고, **보류**는 촬영 자체를 멈춘 상태입니다.

비교 화면에서는 타임라인 위의 **선택 대상**으로 왼쪽/오른쪽을 고릅니다. 반대편에서 사용 중인 기록을 선택하면 두 기록을 교환합니다. **기록 도구**의 PNG 저장·삭제와 원본 확대는 선택 대상의 기록에 적용합니다. 삭제 확인창에서 날짜와 사이트를 다시 확인할 수 있습니다.

## 촬영 범위와 기록 달력

사이트 등록 또는 **사이트 설정 → 촬영 범위**에서 **상단 화면 / 전체 페이지**를 고릅니다. 기존 사이트는 상단 화면을 유지합니다. 범위 변경은 이후 촬영부터 적용되며 기존 이미지는 바꾸지 않습니다. 전체 페이지는 가로 1440px로 고정하고 아래로 스크롤해 일반적인 지연 로딩 이미지를 불러온 뒤 저장합니다. 무한 스크롤·아주 긴 페이지는 높이 20,000px까지 저장하고 해당 기록의 크기 옆에 잘림을 표시합니다. 사이트의 무한 로딩, 가상 목록, 스크롤 동작에 따라 보이는 콘텐츠는 달라질 수 있습니다.

긴 사진은 이미지 영역 안에서 스크롤하며 보고 **원본 확대**로 맞춤/100% 보기를 사용할 수 있습니다. 길이가 다른 두 사진은 슬라이더와 변경 부분 모드에서 상단을 맞추고 남는 공간을 흰색으로 채워 비교합니다. 수동 이미지 가져오기는 기존처럼 1440 × 1000으로 정규화합니다.

사이트 화면의 **기록 달력**을 펼치면 월별로 저장한 사진 수와 실패한 촬영 횟수를 봅니다. 날짜를 누르면 해당 날짜의 타임라인과 상세 이력을 보고, 상세 사진을 누르면 현재 선택 대상(왼쪽/오른쪽/단일)에 엽니다. 촬영 실패 메시지와 다시 촬영 버튼도 표시합니다. 보류 중에는 다시 촬영할 수 없습니다. 달력은 방문자 기기의 시간대를 기준으로 하며 매일 지정 시각 일정은 계속 한국 시간을 사용합니다.

촬영 시도 이력은 SQLite에 별도로 저장하므로 이후 촬영이 성공해도 과거 실패를 확인할 수 있습니다. 이전 사진은 모두 달력에 표시되며, 이전 실패는 기능 추가 시점에 남아 있던 마지막 실패만 가져옵니다. 사진을 삭제하면 달력에서도 해당 사진이 사라지지만 실패 이력은 유지됩니다. 서버가 촬영 도중 종료되면 다음 실행 때 해당 시도를 실패로 표시합니다.

## 기록 정리와 변화 비교

타임라인의 **여러 기록 선택**을 누르면 화면을 눌러 삭제 대상을 고를 수 있습니다. **현재 목록 선택**은 현재 타임라인 페이지에 표시된 기록을, **기간 선택**은 이 사이트에서 지정 기간(양 끝 날짜 포함)에 속하는 모든 기록을 선택에 추가합니다. 기간은 방문자 기기의 날짜 기준입니다. 날짜·중요 필터와 관계없이 지정 기간 전체를 대상으로 하며 선택은 페이지를 넘겨도 유지됩니다. **선택 해제**로 비운 뒤 다시 고를 수 있고 한 번에 최대 500개를 삭제할 수 있습니다. 삭제 확인창은 중요 기록이 포함된 개수도 알려줍니다. 삭제한 이미지와 메모는 복구할 수 없습니다.

화면 아래 **☆ 중요 표시**와 **메모 추가**는 현재 선택한 기록에 적용됩니다. 비교 중에는 타임라인의 왼쪽·오른쪽 선택 대상을 따릅니다. 메모는 최대 1,000자이며 빈 내용으로 저장하면 지워집니다. 중요 표시와 메모는 서버에 저장되고, 타임라인의 **★ 중요 기록만**으로 중요 표시한 사진을 모아볼 수 있습니다.

**변경 부분**에서 두 날짜를 선택하면 오른쪽 기록 위에 달라진 픽셀을 분홍색으로 표시합니다. **작은 차이도 표시 / 보통 / 큰 차이만 표시**로 색 차이 기준을 조절할 수 있고 **비교 PNG 저장**으로 결과를 내보냅니다. 표시 비율은 이 기준을 넘은 픽셀의 비율이며 내용 변경률이 아닙니다. 광고·애니메이션·폰트·위치 이동도 차이로 잡힐 수 있습니다. 원본 기록은 수정하지 않으며 저장된 두 PNG를 브라우저에서 비교합니다.

## 범위와 한계

이 버전은 **개인 컴퓨터에서 실행하는 도구**이며 기본적으로 `127.0.0.1`에 바인딩됩니다. 로그인 세션, 쿠키 동의 자동화, 봇 차단 우회, 클라우드 동기화는 지원하지 않습니다. 로그인이 필요한 사이트나 브라우저 자동화를 차단하는 사이트는 촬영이 실패하거나 차단 화면이 기록될 수 있습니다. 동적 콘텐츠는 촬영 때마다 달라질 수 있고, 변경 부분 모드는 두 이미지의 픽셀 차이를 계산하며 내용의 의미를 해석하지 않습니다.

403 응답은 정상 촬영으로 저장하지 않습니다. 정상적으로 열리는 URL이 다르면 사이트 이름 옆 편집 버튼에서 주소를 수정할 수 있습니다. 사용자가 직접 캡처한 화면은 **내 화면 가져오기**에서 파일 선택·드래그·붙여넣기로 저장할 수 있습니다. PNG/JPG/WebP를 받아 비율을 유지해 1440 × 1000으로 맞추며, 여백이 생길 수 있습니다. 저장 시각으로 기록하고 **직접 가져옴**으로 구분합니다. 이 기능은 차단된 사이트의 서버 자동 수집을 복구하지 않습니다.

촬영 URL과 하위 리소스는 HTTP(S) 및 공개 IP만 허용합니다. 이 검사만으로 DNS rebinding 등 모든 공격을 방어하지는 않습니다. **인증과 네트워크 격리 없이 인터넷에 서버를 노출하지 마세요.** 공개 서비스 전환에는 격리된 촬영 워커, 연결 대상 IP 고정, 인증, 사용량 제한과 보관 정책이 추가로 필요합니다.

UI의 Google Fonts가 차단되면 시스템 폰트로 표시됩니다. 외부 촬영 사이트와 폰트 외에 API 키나 유료 서비스는 필요하지 않습니다.

## 개발

```bash
npm run dev
npm test
```

실제 브라우저와 네트워크를 사용하는 통합 검사는 앱을 실행한 뒤 `npm run test:e2e`로 수행합니다. 포트가 다르면 `REWIND_URL=http://127.0.0.1:4317 npm run test:e2e`처럼 지정합니다. 이 검사는 example.com을 일시 등록해 두 번 촬영하고 마지막에 삭제하므로 해당 주소가 없는 작업 공간에서 실행하세요.

`REWIND_URL=http://127.0.0.1:3000 npm run test:ui`는 브라우저 안에서만 사용하는 테스트 데이터로 검색·필터·비교·날짜 탐색·320px 모바일·연결 복구 등을 검사합니다. 서버의 사이트나 기록은 변경하지 않습니다.

공유 링크는 선택한 두 기록과 보기 방식을 포함합니다. 링크를 받는 사람도 서버에 접속할 수 있어야 합니다. 기록의 날짜와 시간은 방문자 브라우저의 현지 시간대로 표시합니다. 매일 지정 시각 일정과 해당 다음 예정은 한국 시간으로 표시하며, 촬영 브라우저도 서울 시간대를 사용합니다.

- `server.mjs`: HTTP API, SQLite, 촬영 큐, 자동 기록
- `capture-browser.mjs`: Chromium 촬영과 단계별 요청·응답 진단
- `lib.mjs`: URL 정규화와 네트워크 주소 검증
- `public/schedule.js`: 서버와 화면이 공유하는 일정 검증·한국 시간 계산
- `public/`: 빌드 과정 없는 HTML/CSS/JavaScript UI
- `test/`: URL 및 네트워크 경계 테스트

프레임워크 빌드 없이 Node.js 기본 HTTP/SQLite 모듈과 Playwright를 사용합니다.
가져온 PNG 파일 검증과 재인코딩에는 `pngjs`를 사용합니다.

## 제한 시간 내 재점검

POSIX 환경에서 서버는 `data/control.sock`에 소유자만 접근 가능한 로컬 관리 소켓을 만듭니다(권한 600). 별도 TCP 포트나 IP 허용 예외는 만들지 않습니다.

`node scripts/watch-recheck.mjs <등록된-site-id>`는 같은 주소·같은 브라우저 설정으로 30분, 60분, 120분, 180분 간격의 저빈도 재점검을 최대 네 번 실행합니다. 한국 시간 다음 새벽 3시가 상한이며, 새 화면을 얻거나 등록 주소가 바뀌면 일찍 끝납니다. 차단을 해제하거나 우회하는 기능은 아닙니다.

실제 프로세스가 실행 중인 동안 앱에 다음 점검 시간이 표시됩니다. 결과는 `data/recheck-<site-id>.json`, 프로세스 ID는 실행 중의 `.lock` 파일에 저장됩니다. 이 작업은 외부 사이트가 거부하는 요청의 성공을 보장하지 않습니다. `--check-now`는 로컬 관리자가 한 번만 즉시 점검할 때 사용하는 옵션입니다.

## UI 디자인과 시각 검증

아이보리·포레스트 그린을 유지하는 Refined Productivity 디자인을 적용했습니다. 그리드는 스크린샷 탐색에, 목록은 상태·최근 촬영·다음 일정 확인에 맞췄으며 태블릿 탐색 레일과 모바일 메뉴를 제공합니다.

[디자인 감사·토큰·검증 결과](docs/design-review.md)에서 변경 근거와 검증 화면을 확인할 수 있습니다. `REWIND_URL=http://127.0.0.1:4318 npm run test:design`은 해당 서버의 화면에서 브라우저 전용 테스트 데이터로 레이아웃·반응형·메뉴 포커스·텍스트 대비·빈 화면·연결 상태를 검사하고 `test-results/design-after/`에 스크린샷을 저장합니다. 테스트 요청은 브라우저 안에서 가로채므로 운영 사이트를 등록·촬영·삭제하지 않습니다.

## 가독성과 기록 탐색 개선

- 목록에서 기록 방식·주기·촬영 범위를 나눠 보여주고, 최근/다음 촬영에 라벨을 표시합니다. **현재 결과 모두 촬영 (N)**은 검색·필터 결과 중 보류·요청·촬영 중인 사이트를 제외합니다.
- 검색어 지우기는 필터를 유지하며 현재 검색·필터와 결과 수를 함께 표시합니다. 모바일 필터는 뒤쪽 이동 버튼을 제공합니다.
- 등록은 주소와 자동/수동 선택부터 보여줍니다. **촬영 일정·범위**를 펼쳐 상세 설정을 변경하고 제출 전 적용 내용을 확인할 수 있습니다.
- 이미지 근처에서 이전·다음·최신 기록으로 이동하고 비교 간격을 확인합니다. 선택 대상은 왼쪽/오른쪽을 기준으로 하며 이전/이후 표시는 실제 날짜에 따라 바뀝니다.
- 다음 촬영은 남은 시간과 정확한 시각을 함께 표시합니다. 예정 시각이 지나면 그 사실을 표시하고, 보류·수동·진행 중에는 미래 자동 시각을 꾸며내지 않습니다.

[개선 및 검증 보고서](docs/usability-review.md)에 범위·검사·후속 항목을 정리했습니다. `npm run test:usability`는 별도 로컬 서버에서 40개 사이트·300개 기록의 브라우저 전용 데이터로 실행합니다. 모든 API를 가로채므로 운영 데이터를 변경하지 않습니다.

## 분류·촬영 이력·본문 변경 후보

사이트 설정에서 그룹과 태그를 관리하고 목록에서 함께 필터링하거나 검색합니다. **촬영 상태·이력**에서는 성공·실패·진행 중을 조회하고 실패 원인 확인, 다시 촬영, 성공 기록 이동을 제공합니다.

상세의 **변경 찾기**는 새 촬영의 본문 텍스트를 비교해 변경 후보를 찾습니다. 광고·자동 갱신도 포함될 수 있으므로 의미의 변화를 단정하지 않으며, 기존 이미지 기록과 직접 가져온 이미지는 분석 없음으로 표시합니다. 기존 픽셀 비교는 유지합니다.

[사용법·분석 범위·검증](docs/organization-and-activity.md)을 참고하세요. `npm run test:features`는 별도 로컬 서버를 대상으로 모든 API를 브라우저에서 가로채 사이트 160개와 이력 61개의 UI를 검증합니다. `npm test`의 실제 브라우저 본문 추출 검사에는 `npx playwright install chromium`과 브라우저 시스템 라이브러리가 필요합니다.

## Archive & Workspace

미리보기 중심 갤러리와 큰 썸네일 목록, 데스크톱의 중앙 기록 화면·오른쪽 세로 타임라인, 모바일의 하단 기록 탐색 패널을 제공합니다. 기존 기록·촬영 기능을 유지하며 화면 크기에 맞춰 같은 타임라인을 재배치합니다. [디자인 변경과 전후 화면·검증](docs/workspace-redesign.md)을 참고하세요. `npm run test:workspace`는 운영 데이터에 접근하지 않고 새 레이아웃과 기록 탐색을 검사합니다.

기록 탐색 필터는 접힌 상태에서도 적용 조건을 표시하고, 목록은 기록 정보와 촬영 일정을 묶어 보여줍니다. 비교 화면은 선택 대상과 비교 기록을 라벨·테두리로 구분합니다. [세부 개선·전후 화면](docs/design-polish.md)을 참고하세요. `npm run test:polish`는 별도 로컬 서버에서 모든 API를 가로채 이 흐름을 검사합니다.
