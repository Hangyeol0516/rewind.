# Rewind UI/UX 디자인 리뷰

콘셉트: **Refined Productivity SaaS**. 따뜻한 아이보리와 포레스트 그린을 유지하면서 사이트를 찾고, 상태를 확인하고, 기록을 여는 작업에 집중했다.

## 1. 기존 구조와 감사 결과

기존 기술은 빌드 없는 HTML/CSS/ES modules와 Node HTTP API, SQLite, Playwright다. `/`의 쿼리 매개변수가 검색·필터·정렬·보기 방식과 사이트·기록·비교 상태를 복원한다. `app.js`가 화면 상태와 갱신을 관리하고 일정·달력·비교·기록 관리는 기존 모듈이 담당한다. 이름·즐겨찾기 등은 서버에, 보기 설정은 localStorage와 URL에 보존된다.

| 영역 | 유지할 강점 | 문제와 개선 |
|---|---|---|
| 브랜드 | 아이보리·그린과 Rewind 이름 | 보조 텍스트까지 초록색이 반복됐다. 본문은 중성색으로, 브랜드색은 주요 행동·선택 상태에 집중했다. |
| CSS | 가벼운 순수 CSS, 빌드 불필요 | 기능 추가에 따른 중복 덮어쓰기·겹치는 breakpoint가 많았다. 토큰·기초·탐색·아카이브·작업 화면·반응형 순서로 정리했다. |
| 사이드바 | 사이트 간 이동, 이름과 도메인 | 임의의 45vh 스크롤 제한과 모바일 탐색 부재를 개선했다. 유연한 스크롤 영역, 태블릿 레일, 모바일 드로어를 구성했다. |
| 헤더 | 페이지 목적과 사이트 추가 CTA | 제목·통계·도구의 강조 수준이 비슷했다. 페이지 목적 → 요약 지표 → 작업 도구 → 사이트 목록의 계층을 만들었다. |
| 통계 | 사이트·기록·자동 촬영이라는 실제 데이터 | 카드와 장식 아이콘을 줄이고 숫자·라벨·구분선으로 정돈했다. |
| 검색·필터 | 검색, 정렬, 보기 전환, URL 복원 | 높이·간격이 제각각이었다. 검색창과 선택 컨트롤을 통일하고 필터를 밑줄 탭으로 묶었다. |
| 사이트 목록 | 실제 스크린샷, 상태, 일정, 즐겨찾기 | 그리드와 목록이 거의 같은 카드였다. 그리드는 미리보기 중심으로, 목록은 열 정렬과 빠른 비교에 맞춰 나눴다. |
| 상태 | 자동·수동·보류·진행·오류 구분 | 작은 라벨과 비슷한 색에 의존했다. 텍스트·표시점·절제된 의미 색을 함께 사용했다. |
| 작업 화면 | 비교, 확대, 타임라인, 달력, 메모 | 동작을 유지하면서 버튼 크기·아이콘·표면·메뉴·입력 요소를 같은 시스템으로 정리했다. |
| 빈 화면·로딩 | 이미 존재하는 안내와 연결 복구 | 장식적인 요소를 줄이고 다음 행동을 직접 설명했다. 카드 상승 효과도 제거했다. |

실제 favicon 데이터는 제공되지 않으므로 도메인 이니셜을 일관된 로컬 대체 아이콘으로 사용한다. 외부 favicon 서비스에 새 요청을 만들지 않는다.

## 2. 시각 시스템

- 색: canvas `#f8f7f3`, surface `#fffefa`, navigation `#f0f1eb`, primary `#2e5843`, text `#27322c`, muted `#616d63`, border `#dfe4da`.
- 상태: 자동 기록은 그린, 촬영 진행은 차분한 블루, 접근 거부·실패는 앰버, 삭제·오류는 레드, 수동·보류는 중성색.
- 글꼴: 기존 DM Sans / Noto Sans KR와 시스템 대체 글꼴. 제목 30px, 섹션 16px, 본문 14px, 컨트롤 13px, 보조 정보 11–12px. 날짜·수치에는 tabular numerals 적용.
- 간격: 4/8px 기준으로 4, 8, 12, 16, 24, 32, 40, 48px 사용. 관련 정보는 조밀하게, 작업 영역 사이에는 더 큰 간격을 둔다.
- 컨트롤: 기본 36px, 작은 도구 32px, 주요 CTA 40px. 모바일 주요 조작 영역은 별도로 조정했다.
- 모서리: 4/6/8px 컴포넌트, 12px 다이얼로그. 그림자는 떠 있는 메뉴·다이얼로그에 집중했다.
- 아이콘: 로컬 SVG, 기본 16px·1.75px 스트로크. 별도 라이브러리나 외부 아이콘 요청은 없다.
- 인터랙션: 160ms 색·테두리 전환, 명확한 focus ring, 선택·눌림·비활성 상태, reduced-motion 지원. 카드 확대·상승 동작은 없다.

## 3. 정보 구조와 반응형 설계

1. 워크스페이스 탐색과 스크롤 가능한 사이트 목록.
2. 페이지 제목·짧은 설명·사이트 추가.
3. 조용한 세 가지 요약 지표.
4. 검색·정렬·보기 방식 도구 모음, 필터·결과 수·일괄 촬영.
5. 미리보기 중심 그리드 또는 상태·일정 중심 목록.
6. 기존 사이트 작업 화면에서 촬영·비교·기록 관리.

데스크톱은 전체 사이드바와 열 정렬된 목록을 사용한다. 태블릿은 이름과 접근성 레이블을 보존한 탐색 레일을 사용한다. 모바일은 고정 헤더·메뉴 드로어·검색·가로 스크롤 필터와 작은 썸네일의 목록 행을 사용한다. 화면을 단순히 세로로 쌓는 방식과 구분했다.

## 4. 검증과 수정

Chromium에서 1440, 1024, 768, 390, 320px를 검사했다. 스크린샷을 검토한 뒤 검색창의 이중 테두리, 오류 행의 열 밀림, 태블릿 상태 아이콘 위치, 보조 텍스트 대비, 모바일 메뉴에서 다이얼로그를 닫은 뒤 포커스 복귀를 수정했다.

- `scripts/design-check.mjs`: 그리드·목록·작업 화면, 오류/빈 화면/로딩/연결 복구, 가로 넘침, 목록 열 정렬, 도구 높이, 드로어 Tab/Escape·포커스 복귀, 48개 사이트에서 탐색 스크롤 유지 검사.
- 대표 보조 텍스트 세 종류는 실제 계산 색상으로 4.5:1 이상 대비 확인. 전체 접근성 인증을 의미하지는 않는다.
- `npm run test:ui`: 기존 검색·필터·URL·스크롤 복원·즐겨찾기·촬영·보류·비교·메뉴·확대·모바일 동작 통과.
- `scripts/page-calendar-check.mjs`: 분 단위 일정·전체 페이지 설정·긴 사진 비교·확대·달력·실패 이력·시간대·모바일 검사 통과.
- `scripts/record-tools-check.mjs`: 일괄 삭제·메모·중요 표시·비교 대상·PNG 저장·모바일 검사 통과.

시각 검증은 브라우저 안의 명시적인 테스트 데이터로 수행했다. 운영 사이트 등록이나 사진은 변경하지 않았다. Safari/Firefox 및 실제 스크린리더 기기 검증은 이번 범위에 포함하지 않았다.

## 5. 최종 디자인 판단

| 질문 | 판단과 근거 |
|---|---|
| 시각적 완성도가 개선되었는가? | 텍스트 역할, 입력 크기, 테두리, 아이콘, 정렬 기준을 통합하고 화면별 스크린샷으로 검토했다. |
| 정보 구조도 개선했는가? | 미리보기 위의 식별 정보, 분리된 상태·메타데이터, 실제 목록 열, 통합 도구 모음과 모바일 탐색을 구현했다. |
| 브랜드가 유지되는가? | Rewind 이름과 되감기·시간의 로고 의미, 아이보리·포레스트 그린을 유지했다. |
| 일반적인 SaaS 템플릿처럼 보이지 않는가? | 실제 사이트·스크린샷·촬영 일정에 집중했다. 허구의 차트·결제·팀·사용량 지표를 추가하지 않았다. |
| 크기·간격·정렬이 일관적인가? | 토큰과 공통 컨트롤을 적용하고 목록 열과 도구 높이를 자동 검사했다. |
| 핵심 작업이 더 명확한가? | 이름·도메인·저장 수·최근·다음 촬영을 구분하고 모바일에서도 검색·추가·사이트 이동을 제공한다. |
| 실제 서비스에 적용 가능한가? | 기존 기능 검사를 통과했고 프레임워크·API·데이터 모델·촬영 엔진·스케줄러를 변경하지 않았다. |
