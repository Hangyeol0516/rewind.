# 가독성·탐색·촬영 흐름 개선 보고서

이 문서는 기존 아이보리·포레스트 그린 디자인과 촬영·저장·비교 기능을 유지하면서 진행한 개선을 정리한다.

## 구현한 변경

| 문제 | 변경 및 사용자 효과 |
|---|---|
| 주소·시간·설명이 작음 | 자주 확인하는 주소·촬영 시각·일정·상태를 13–14px로, 주요 본문을 15px로 조정했다. 기존 대비·hover·선택·키보드 focus 구분을 유지했다. |
| 통계와 상단 도구가 목록을 밀어냄 | 세 통계를 한 줄로 묶고 중복 설명·구분을 줄였다. 모바일 설명은 핵심 작업에 자리를 양보한다. |
| 일괄 촬영 범위 불명확 | ‘현재 결과 모두 촬영 (N)’으로 바꾸고 실제 검색·필터 결과에서 보류·요청·촬영 중인 대상을 제외한 수를 표시한다. 요청 중 중복 배치 실행을 막는다. |
| 상태·주기·범위 혼합 | 목록에서 기록 방식과 촬영 범위를 분리했다. 방식 안에서도 자동/수동/보류/진행 상태와 설정 주기를 별도 줄로 구분한다. |
| 모바일에서 시간이 무엇을 뜻하는지 모호 | 최근 촬영·다음 촬영 라벨을 표시하고 정확한 시각을 함께 유지한다. |
| 아이콘 실행 버튼이 불명확 | ‘기록 보기’와 ‘촬영’이라는 텍스트 버튼을 제공한다. 이름·썸네일·기록 보기는 같은 상세 진입 함수를 사용한다. 즐겨찾기·촬영은 독립 버튼으로 유지한다. |
| 뒤쪽 필터 발견이 어려움 | 뒤쪽 이동 버튼을 제공하고 선택된 필터를 노출한다. 현재 조건 요약에서도 선택 상태를 확인할 수 있다. |
| 등록 설정이 한꺼번에 노출됨 | URL과 자동/수동 선택부터 보여주고 상세 일정·범위는 접는다. 제출 전 적용 내용을 요약하고 제출 영역을 스크롤 본문과 분리했다. 오류가 있는 상세 필드는 자동으로 펼쳐 포커스를 옮긴다. |
| 상세의 설정이 이미지 접근을 방해함 | 조회에 필요한 도구는 이미지 근처에, 촬영 설정은 이미지 아래의 접을 수 있는 영역에 배치했다. 다음 촬영의 요약은 상단에서 확인한다. |
| 비교 대상·메모 대상 불명확 | 날짜 선택 바로 위에 선택 대상 버튼을 배치했다. 좌우 교환을 텍스트 버튼으로 노출하고, 실제 날짜에 따라 이전/이후를 계산한다. 중요 표시·메모에도 적용 대상과 시각을 명시한다. |
| 모바일 축소 화면 판독 어려움 | ‘원본 확대’를 강조하고 주요 터치 영역을 44px 이상으로 조정했다. 확대 창 종료 시 포커스·페이지·이미지 내부 스크롤을 복원한다. |
| 용어 혼용 | 저장한 결과는 ‘기록’, 저장하는 동작은 ‘촬영’으로 통일했다. 업로드 파일을 설명하는 ‘이미지’는 유지한다. |

## 추가한 작은 기능

1. **최신 기록 이동**: 단일 보기와 비교 보기 모두 현재 선택 대상에 적용한다. 다른 쪽이 최신인 경우 기존 교환 규칙을 유지해 같은 기록이 양쪽에 중복되지 않는다.
2. **비교 간격**: 초·분·시간·일 단위 간격을 표시한다. 시간 순서를 뒤집으면 이전/이후 라벨도 함께 바뀐다.
3. **검색어 지우기·조건 요약**: 검색만 지울 때 필터는 유지하며, 검색어·필터·결과 수를 요약한다.
4. **다음 촬영 상대 시간**: ‘8분 후’와 정확한 시각을 함께 보여준다. 시각이 지났다면 원래 예정 시각을 보존하고 ‘예정 시각 지남’으로 표시한다. 보류·수동·요청·촬영 중인 상태를 미래 자동 시각으로 오표시하지 않는다.

시간 표시 유틸은 스케줄러의 실행 로직을 변경하지 않는다. API·DB 모델·촬영 엔진도 유지하며, 새 화면 유틸을 제공하는 정적 파일 경로만 추가했다.

## 검토와 검증

요청한 추가 리뷰 에이전트와 독립적으로 코드·사용자 흐름을 검토했다. 검토 결과 예정 시각의 clamp에 따른 ‘0분 후’ 오표시, 좌우 교환 뒤의 잘못된 시간 관계, 모달 Tab 이탈, 이미지 앞 도구 영역의 높이를 조정했다.

- 단위 검사 **27개 통과**. 새 일정·비교 표시 검사 11개는 서울·LA 시간대에서도 확인했다.
- `scripts/usability-check.mjs`: 브라우저 전용 **40개 사이트·300개 기록**으로 검색·필터·촬영 범위·중복 방지·최신/이전/다음·좌우 교환·시간 간격·메모 대상·등록 및 설정 모달·원본 확대 복귀 검사 통과.
- 등록·설정·확대 창의 Tab/Shift+Tab 내부 이동, Escape 닫기, 원래 버튼의 포커스 복귀를 확인했다.
- **1440/768/390/360px** 신규 흐름과 **320px** 추가 시각 검사에서 페이지 가로 넘침이 없었다. 의도된 필터·타임라인 스크롤은 유지한다.
- 기존 `test:ui`, `test:records`, `test:page-calendar`, 일정 검사, `test:e2e` 통과. 등록·실제 촬영·PNG·단일/슬라이더/나란히/변경 부분·일정·중요 표시·메모·삭제 흐름을 확인했다.
- 실제 DB가 필요한 검사는 `/tmp/` 아래의 분리된 데이터 경로에서 수행했다. 운영 데이터를 쓰는 테스트는 없다.
- 운영 검토는 모든 비-GET API 요청을 차단한 별도 브라우저로 수행했다. 전후 사이트·기록 ID를 비교해 기존 항목 보존을 확인했다.

검토 당시 보고된 기록 수와 실제 작업 시작 시점의 수는 다를 수 있다. 운영 서버의 기존 자동 촬영은 작업 중에도 유지했다. 새 테스트 사이트를 운영에 추가하거나 운영 기록을 삭제하지 않았다.

## 구현하지 않은 항목과 후속 작업

- **행 전체 클릭은 도입하지 않았다.** 이름·썸네일·‘기록 보기’로 진입 규칙을 통일하고 즐겨찾기·촬영과의 충돌을 피했다.
- 태그·그룹 분류, 실패 원인과 재시도 이력 전용 화면, 의미 있는 변경을 찾는 기능은 후속으로 남겼다. 이번 범위를 위해 큰 데이터 구조나 새 인프라를 도입하지 않았다.
- 변경 부분은 계속 픽셀 차이로 설명한다. 광고·애니메이션·위치 이동도 차이로 잡힐 수 있다는 안내를 유지하며 내용 변경으로 단정하지 않는다.
- Chromium에서 검증했다. 다른 브라우저 및 실제 스크린리더 기기 인증은 이번 검증 범위에 포함하지 않는다.
